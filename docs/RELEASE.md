Experimental Dalamud API 15 build 0.0.1.8 adds persistent rejection evidence and twenty-second timing/count snapshots to the cached MCP status. A transient hidden update can now be diagnosed after rendering recovers, without waiting for an IPC sample to coincide with the failure or relying on an uncapped log file. The value snapshot reuses existing status text; it adds no per-rejection geometry traversal or native query. Collision, publication, foot and render acceptance rules are unchanged.

Three bounded visual motion probes reproduced one center-floor Pending update: one ray had run and the update had already taken 6.36 ms when the next query was deferred by the existing 2 ms sampling deadline. The following three twenty-second windows published all 2,978 updates. Their peak complete update/build costs were 5.65/3.75 ms; the initial window had substantially higher peaks (67.16/20.65 ms). These are observed maxima, not percentiles, attribution to a particular native call, or a guarantee against future stalls. Do not hide the recorded refusal by widening freshness or query budgets.

Live backbuffer/display resize from 1920×1080 to 1600×900 and back retained supported cloth and recent render submissions without fault flags. Actual screenshots at both resolutions show the rug. The original resolution was restored. All 1,613 existing offline tests remain the regression baseline; both final plugin variants compile cleanly. Actual character walking, jumping, mounts, zone transitions, full client startup and broader profiling remain pending.

The preceding 0.0.1.7 repair addresses the reproduced Limsa planter disappearance. A sloped face on a raised object was being treated as a floor continuation, making the sampler wait indefinitely for a nonexistent floor portal. The new check identifies an actual clearance hit above a fresh locally reached floor, then stops the cloth before that hit. It does not add the object to the floor graph, widen floor tolerances, shrink the material window or bypass contact/cell validation. Connected ramps retain their existing floor-path checks.

Validation: all 1,613 offline tests pass, including eight new captured-geometry, connected-ramp, malformed-hit, deadline and empty-layer cases. Normal and compatibility builds compile without warnings. At the formerly permanently hidden location, a 48-second sampled interval published all 2,218 support updates and submitted 2,217 draws; the recording and screenshots show the rug. A 32-second interval containing the bounded visual motion probe published 1,466 of 1,468 support updates and submitted 1,459 draws. All status samples were visible, but two withheld updates mean this is not a claim of flicker-free movement. These counters are not displayed-frame percentages.

The ten-second map outage probe retained woven rendering and restored the current map automatically. Native-composition fallback and background composition both produced visible cloth, and the user's native-composition setting was restored. The diagnostic target does not move the character, so actual walking, stairs, jumping, mounts, zone changes, device resizing and broader runtime profiling remain unverified. See docs/stability-audit.json; the overall stability goal remains active.
